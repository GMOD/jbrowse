This is a patch release that fixes building from source on a fresh clone.

JBrowse 1.17.0 fixed the node-sass build failures, but `./setup.sh` still could
not complete on a new checkout: the step that bootstraps yarn also caused npm to
rewrite `yarn.lock` into npm's own format, which yarn is then unable to read,
failing with `SyntaxError: Invalid value type`. Setup now leaves the lockfile
alone, and repairs it automatically if an earlier run damaged it.

If you hit this on 1.16.12, 1.16.13 or 1.17.0, this release fixes it — no manual
cleanup needed.

## Build

- Stop `setup.sh` from corrupting `yarn.lock` before yarn reads it. Its
  `npm install yarn` step ran in the project root, and npm 7+ rewrites an
  existing `yarn.lock` into its own dialect, which yarn 1 cannot parse, so a
  fresh `./setup.sh` failed with `SyntaxError: Invalid value type` (issue
  #1675)
